Yagni Principal
===============
- stands for Your Aren't Gonna Need It
- promotes simplicity
- encourage avoiding unnecessary functionality until it is needed
- core idea:
    - focus on immediate project requirements
    - minimize unnecessary complexity and effort
- extreme programming:
    - is an agile software development methodology
    - focuses on improving software quality and responsiveness to changing customer requirements through frequent releases in short development
    - introduces checkpoints where new customer requirements can be adopted

Critical costs in software development
--------------------------------------
- cost of build:
    - involves resources invested in developing features (planning, coding, testing)
    - YAGNI minimizes the cost by avoiding speculative features
- cost of delay:
    - refers to the impact of not delivering a feature promptly
    - YAGNI ensure essential features are delivered quikly, avoiding delays
- cost of carry:
    - relates to the ongoing work of maintaining features
    - YAGNI reduce this cost by avoiding unnecessary complexity and simplifting the codebase
- cost of repair:
    - incurred when fixing and maintaining suboptimal features
    - YAGNI helps minimize technical debt by avoiding premature optimization and focusing on immediate needs

Benefits
--------
- simplified codebase
- increased productivity
- enhanced quality:
    - fewer features to test allows for more rigorous and through testing
    - reduces the potential for introducing bugs by not implementing speculative features
- better reponsiveness ot change
- cost efficiency
- increased customer satisfaction

How to apply
------------
- focus on essential features:
    - start with Minimum Viable Product (MVP)
    - avoid speculative features
- Embrace incremental development:
    - iterative approach
    - continuous feedback
- Refactor and Simplify Constinuously
- Prioritize Delivering Value
    - Value-Driven development
    - just in time decision: postpone decisions about future features until are necessary to avoid wasted effort
- avoind premature optimization
- use agile practices
- validate assumptions:
    - data-driven decisions
    - prototyping and testing:
        - use prototypes and user testing to validate assumptions early in the development process

Yagni vs KISS
-------------
- Yagni:
    - focus on immediate requirements
        - implemet only features necessary for the current iteration or immediate requirements
        - avoid adding functionalities based on anticipated future needs
    - avoid over-engineering:
        - avoid premature optimization and over-engineering
    - iterative development:
        - software development is based on real user feedback
        - add feature incrementlly as they are validated by user needs
        - requirements can be changed
- KISS:
    - simplicity in Design:
        - keep code and design as simple as possible
        - choose straighforward solution over complex ones to prioritize clarity and easy of understading
    - minimalist:
        - advotate for minimalist designs and implementation that are easy to maintain, debug and extend
    - user-centric approach:
        - focus on end-user experience, creating intuitive interfaces and functionalities
