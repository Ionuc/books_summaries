Kiss Principal
==============
- stands for Keep it Simply, Stupid
- simplicity should be a key goal in design
- unnecessary complexity should be avoided

- asserts that sytem, design and processes should be kept as simple as possible

- key concepts:
    - simplicity:
        - strive for simplicity in design and implementation
        - simple systems are easier to understand, debug and maintain
        - avoid over-engineering adn complexity that does not add direct value
    - avoid unnecessary complexity:
        - do not add features or functionalty that are not necessary for current requirements
        - avoid "gold-platig" or adding emelshments that do not contribute to the core functionality
    - easy of understanding:
        - code and designs should be easy to read and understand for other developers
        - use clear and straighforward logic rather than convulated algorithms or patterns
    - maintainability:
        - simple systems are easier to maintain and extend
        - fewer compoenents and less complex interactions reduce the likelihood of bugs and issues
    - efficiency:
        - simplicity often leads to more efficient use of resource
        - streamlined design can lead to better performance and lower costs in development and maintenance

- benefits:
    - improve readability and understandability
    - enhance maintainability
    - increased flexibility and adaptability
    - cost efficiency
    - eter collaboration and communication
    - higher realiability and stability
    - improve performance

- how to apply:
    - simplify requirements:
        - understand the core requirements
        - avoid adding features based on speculative future needs(alligned with YAGNI principal: You aren't gonna need it)
        - work with stakeholders to prioritize features that provide the most value
        - keep the initial scope limited to essential functionalities
    - design with Simplicity in Mind:
        - choose straghtforward architectural patterns suitable fr the problem
        - avoid over-engineering with complex frameworks
        - design your system in small, manageable and independent modules
        - ensure each module as a single responsibility
    - write clean and clear code:
        - adhere to coding standards and best practices
        - write code that is easy ti read and understand
    - simplifiy logic and algoriths
        - constinuously refactor code
        - break down the complex methods int osmaller ones
    - minimize dependencies:
        - only use external libraries that are necessary
        - encapsulate dependencies within well-defined interfaces
    - simplify user interface
    - document clearly and concisely:
        - ensure documents are up-to-date
        - avoid excesive details
    - automate and simplify testing
    - continuous integration and deployment:
        - use Ci/CD pipelines ti automate build, tests and deployment process
